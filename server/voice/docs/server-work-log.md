## 2026-11-01 语音分段与长期事实记忆

- 首段达到默认 18 字且遇到逗号/分号等短语边界时可以提前合成，后续继续按句处理；修复小数点跨模型片段被误断的问题。保留现有流式转码、提前合成和实机 60 ms 发送节奏。
- 新增首句就绪、合成请求开始、首 PCM、发送包数和音频时长计时，测试页显示阶段时间，日志汇总脚本支持新字段。
- 相关历史按匹配度排序，排除已在近期上下文中的消息，并附原文出处；历史资料和事实分别设字符预算。
- SQLite 新增长期事实及主题排除记录，支持来源、偏好更新、遗忘和设备隔离；旧数据库增量建表，不清空历史。管理 API 增加事实查看、更新、遗忘，测试页显示当前事实。
- 普通对话默认空闲 20 秒后批量整理，后台一次生成摘要和事实；实际讲话或新文本会取消后台任务。明确记忆命令当轮落库后再确认，增加一次模型请求的耗时。
- 真实 GLM 检查曾出现组合类别和错误的遗忘 action；类别改由事实键确定，明确遗忘由代码决定操作，来源仍必须对应本批用户原文。
- 原生自动监听在讲话前只保留短缓冲，不累计闲置录音时长；到录音上限自动提交。修复自动监听切手动时未切换模式的问题。
- 中断时保存已发送段落，部分发送与尚未确认设备播放均明确标记，不保存后续完全未发送的段落。
- 明确命令直接处理当前用户原文，不被旧批次积压挡住，也不跳过普通历史整理；已遗忘值不再送入整理提示，后续摘要继续清理该主题。
- 离线回归：375 项 Python、16 项浏览器逻辑通过；测试环境安装已固定的 edge-tts 7.3.1 后，原先跳过的握手测试也通过。
- 临时库中的真实 GLM“记住→改口→忘掉”检查通过；独立真实语音单次检查：ASR 142.7 ms、记忆 1.7 ms、首文字 846.7 ms、首句 928.0 ms、首 PCM 3274.7 ms、首 Opus 3275.6 ms、pipeline 总计 8829.0 ms，输出音频帧时长约 4.5 秒。
- 新增临时随机端口、实际 WebSocket 的 30 轮串行检查，全部成功；ASR P50/P95 为 93.3/108.7 ms，首音频 3471.7/6919.9 ms，pipeline 结束 7619.3/11911.2 ms。TTS 请求到首 PCM 为 2448.7/2916.6 ms。输入为固定 2.064 秒合成语音、空历史，未含真实麦克风、VAD 等待和设备播放。
- 本地合成历史补测：500 条历史加 20 条事实时，实际写入＋检索 P50/P95 为 2.4/2.7 ms；5000 条时为 18.0/18.4 ms。每规模 30 轮，临时库，不调用模型；不把空历史性能推广到所有规模。
- 固定文本流、真实 TTS 的每模式 30 轮受控对比：短首段的首音频中位数提前约 450 ms，但发送完成中位数慢约 122 ms，多一次请求且音频增加 540 ms；不能声称整轮普遍提速。实际 Silero 合成样本对比中，450 ms 在 540 ms 句中停顿处误切，600 ms 保持整段，因此保留默认值。
- 没有改动真实记忆数据库和本机运行配置。已备份真实库，并在另一个副本上增量迁移，553 条消息、5 条摘要均保留。实机播放、自然停顿和插话打断仍待用户配合验收；详细结果见 [实施记录](../../../docs/voice-memory-implementation-2026-11-01.md)。

## 2026-10-11 本地语音服务稳定性与动作边界

- 增加可配置的本地命令 TTS：命令从 stdin 读取 UTF-8 文本，向 stdout 输出 24 kHz 单声道 s16le PCM；Edge TTS 仍为默认 Provider。
- 增加 `/readyz` 启动就绪检查、LLM 重试配置、发送超时、WebSocket 帧上限和同设备旧会话替换。

- 回归结果：342 项 Python、16 项浏览器逻辑、7 项启动器测试通过；真实模型、Edge 网络和原生硬件仍需现场验收。

## 当前服务

- `8000`：设备语音 WebSocket，路径为 `/xiaozhi/v1/`。
- `8003`：OTA 配置与健康检查，设备地址为 `http://<服务器局域网地址>:8003/xiaozhi/ota/`。
- `8004`：仅监听本机的管理 API，提供在线会话和设备历史记录查询。
- `8006`：浏览器本地测试页，使用 `http://127.0.0.1:8006/` 打开。

## 已完成的服务器工作

- 管理 API 增加在线会话列表，测试页每 2 秒刷新设备 ID、会话 ID、连接时长和当前阶段，支持多台实机同时连接。
- 对话历史按 `Device-Id` 隔离保存，测试页可以加载当前设备或指定设备的最近消息和记忆摘要。
- `auto` 和 `realtime` 监听模式在一轮 `tts.stop` 后自动重新进入监听；`manual` 模式保持原有的再次唤醒流程。
- 默认对话回复限制为最多三句话、每句话尽量不超过 60 个汉字，并继续按句生成语音。
- 面向实机的 Opus 音频包按 60 ms 音频帧节奏发送，避免长回复一次性涌入设备播放队列；浏览器测试桥仍由浏览器本地调度。
- 本地测试页保留摄像头 MCP、视觉对话、健康检查、日志导出和模型选择功能；启动器可以选择 ninfer、Ollama 或智谱模式并打开测试页。
- 实机 MCP 已接入语音工具循环：设备在 hello 中声明 `features.mcp=true` 后，服务器会读取工具清单，将运动、IMU 和实机摄像头工具提供给模型，并通过原 WebSocket 转发调用结果。运动调用限制为 1 到 5000 毫秒；设备断开时清理待处理请求。
- 立创实战派固件在启动时提前注册 `self.camera.take_photo`，相机硬件约 3 秒后初始化；调用工具时再读取就绪的相机并应用已缓存的视觉服务配置。旧固件只在启动时检查相机指针，会遗漏延迟初始化的相机能力；刷入包含提前注册修复的固件后，重新连接设备即可在卡片中看到拍照工具。

## 已知运行条件

- 设备与服务器必须在同一个局域网，OTA 地址中的服务器 IP 需要使用服务器当前局域网地址。
- 浏览器测试页要使用 HTTP 地址，直接打开 `file:///.../index.html` 时不会正常读取本地 API。
- 语音对话还依赖配置的 LLM 和 Edge TTS。“服务暂时不可用”是通用错误提示，需要根据设备卡片的失败阶段和 voice.log 区分识别、模型、工具或合成问题。
