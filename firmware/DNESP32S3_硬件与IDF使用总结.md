# DNESP32S3 开发板硬件与 ESP-IDF 使用笔记

> 基于以下两份官方资料整理：  
> 1. 《DNESP32S3 V1.0 硬件参考手册》（V1.0，2024-02-28）  
> 2. 《DNESP32S3 开发板使用前必看说明（IDF版）V1.0》（V1.0，2024-05-21）

---

## 1. 开发板定位

DNESP32S3 是正点原子基于 ESP32-S3 的综合开发板，主控模组为 **ATK-MWS3S**，面向 HMI、AIoT、音频、摄像头、显示、传感器和网络应用。

这块板子的特点不是“只有一个 ESP32-S3”，而是已经集成了大量外围资源，因此开发时最重要的一点是：

> **很多 GPIO 已经被板载外设复用，不能把所有引脚都当成完全空闲 GPIO 使用。**

---

## 3. 板载资源总览

### 3.1 存储资源

- 16 MB Flash
- 8 MB PSRAM
- 24C02 EEPROM：2 Kbit，即 **256 Byte**
- TF / Micro SD 卡接口

EEPROM 适合保存少量掉电不能丢失的数据，例如系统设置、校准参数等。

---

### 3.2 人机交互资源

- 1 个蓝色电源指示灯 PWR
- 板载红色 LED（LED 连接 IO1）
- RESET 复位按键
- KEY0、KEY1、KEY2、KEY3、BOOT 共 5 个按键
- 有源蜂鸣器
- 红外接收头
- 红外发送头

其中：

- KEY0～KEY3 通过 **XL9555 I/O 扩展芯片**读取。
- BOOT 连接 IO0，启动后也可以作为普通低电平有效按键使用。
- 蜂鸣器同样不是直接由 ESP32-S3 GPIO 控制，而是通过 XL9555 的 P0_3 间接控制。

---

### 3.3 板载传感器

#### AP3216C 光环境传感器

可检测：

- 环境光强度
- 接近距离
- 红外光强

接口：I2C

- SDA → IO41
- SCL → IO42

#### QMA6100P 三轴加速度计

用于检测 X/Y/Z 三轴加速度，可用于姿态和运动状态感知。

#### DS18B20 / DHT11 接口

支持：

- DS18B20 / DS1820
- DHT11 等数字温湿度传感器

数据线 `1WIRE_DQ` 连接 **IO0**。

注意：IO0 同时还承担 BOOT 和部分扩展功能，因此使用时要考虑复用关系。

---

## 4. 音频系统

开发板已经具备比较完整的音频链路。

### 4.1 ES8388 音频 Codec

板载 **ES8388** 音频编解码芯片：

- 24 bit ADC / DAC
- 最高支持 192 kHz / 24 bit 音频
- 支持麦克风输入
- 支持耳机输出
- 使用 I2S 与 ESP32-S3 通信

### 4.2 板载音频器件

- 板载 MIC
- 3.5 mm PHONE 耳机输出
- 板载 8 Ω / 1 W 扬声器
- MD8002A 功率放大器，最大输出约 3 W

ES8388 本身不能直接驱动板载喇叭，因此通过 MD8002A 功放驱动。

### 4.3 I2S 引脚

| I2S 信号 | GPIO |
|---|---:|
| MCLK | IO3 |
| SCK / BCLK | IO46 |
| LRCK / WS | IO9 |
| SDIN | IO10 |
| SDOUT | IO14 |

这些引脚同时还和 RGB LCD 等资源存在复用关系，使用音频功能时不能忽略冲突。

---

## 5. 显示接口

开发板有两类显示扩展方式。

### 5.1 RGB LCD

- 使用 RGB565 数据格式
- 支持触摸屏
- 官方手册注明：该接口只支持 RGB 接口液晶，不支持 MCU 接口液晶
- 手册明确写的是 **正点原子 4.3 寸 RGB 屏**

RGB LCD 会占用大量 GPIO，是板上最重要的 IO 消耗源之一。

### 5.2 SPI LCD / WIRELESS 接口

WIRELESS 接口可以接：

- NRF24L01
- RFID 模块
- 正点原子 1.3 寸 SPI LCD
- 正点原子 2.4 寸 SPI LCD

如果使用 NRF24L01 做通信，官方示例通常需要两块板和两个无线模块才能完成收发测试。

---

## 6. 摄像头接口

开发板提供 P2 OLED / 摄像头接口，可连接正点原子摄像头模块。

摄像头与 RGB LCD 共用了大量 GPIO，包括：

| 摄像头信号 | GPIO | 同时复用 |
|---|---:|---|
| D0 | IO4 | LCD_DE |
| D1 | IO5 | LCD_CLK |
| D2 | IO6 | LCD_B7 |
| D3 | IO7 | LCD_B6 |
| D4 | IO15 | LCD_B5 |
| D5 | IO16 | LCD_B4 |
| D6 | IO17 | LCD_B3 |
| D7 | IO18 | LCD_G7 |
| VSYNC | IO47 | LCD_R5 |
| HREF | IO48 | LCD_R4 |
| PCLK | IO45 | LCD_R3 |
| SCL | IO38 | 触摸 SCL |
| SDA | IO39 | 触摸 SDA |

因此：

> **RGB LCD 与摄像头不是两套完全独立的引脚资源。**

如果后续同时使用摄像头、RGB 屏、音频和其他外设，一定要先画一份 GPIO 占用表。

---

## 7. TF / Micro SD 卡

开发板背面提供 TF 卡槽，可用于大容量数据存储。

硬件参考手册中存在一处需要特别注意的**内部表述不一致**：

- 前面的资源说明把 TF 卡描述为 **SDIO 方式驱动**；
- 后面的原理图详解明确写为 **SPI 方式驱动**，理论最大速度约 24 MB/s，并注明 **TF 卡与 SPI LCD 共用一个 SPI 接口**。

结合 IO 表，SPI2 相关引脚为：

| SPI 信号 | GPIO |
|---|---:|
| MOSI | IO11 |
| SCK | IO12 |
| MISO | IO13 |
| TF_CS | IO2 |

因此在实际项目中，不要仅凭前面的概览文字判断 TF 卡总线方式，应该进一步以：

1. 对应开发板原理图；
2. 正点原子 TF 卡示例工程；
3. 实际 ESP-IDF 配置；

为准。

另外，**TF 卡与 SPI LCD 共用 SPI 总线**，如果两者同时使用，需要正确处理片选和总线共享。

---

## 8. USB 与串口

### 8.1 USB_UART

板载 CH340C USB 转串口芯片。

USB_UART Type-C 接口同时承担：

- USB → TTL 串口
- 程序下载
- 串口调试
- 开发板主要 USB 供电

### 8.2 USB SLAVE / JTAG

另一组 Type-C 接口为 `USB_SLAVE / JTAG`，可用于：

- USB CDC
- USB MSC
- USB HID
- JTAG 下载与调试

USB 数据线对应：

- USB D- → IO19
- USB D+ → IO20

### 8.3 USB 串口跳线帽

P4 上使用两个跳线帽连接 CH340C 与 ATK-MWS3S 的 UART0。

拔掉跳线帽后，可以把：

- CH340C 当成独立 USB-TTL 使用；
- ATK-MWS3S UART 接到其他 TTL 串口设备。

这也是调试串口问题时首先应该检查的位置之一。

### 8.4 手册中的另一处需核对表述

硬件手册中有一句“USB HOST 和 USB SLAVE 共用 PA11 和 PA12，因此不能同时使用”，但同一手册的 IO 表将 USB D-/D+ 标为 **IO19 / IO20**。

这里存在命名/文档一致性问题。实际开发 USB HOST/Device 功能时应以该版本开发板原理图和 ESP32-S3 官方 USB 引脚定义为准，而不要直接照抄 `PA11/PA12` 这一句。

---

## 9. 电源系统

### 9.1 USB 供电

开发板主要通过 USB_UART Type-C 口供电。

单个 USB 口按手册建议最多按 **500 mA** 考虑。

如果同时使用：

- LCD
- 摄像头
- Wi-Fi
- 扬声器
- 多个外部模块

总功耗可能明显增加，USB 线压降也可能导致实际板端电压低于 5 V。

官方手册建议在大负载时可同时插两个 USB 口增强供电能力。

### 9.2 板载电源转换

- RT9013-33GB LDO：5 V → 3.3 V
- F1：1000 mA 自恢复保险丝
- 总电源开关：K1

### 9.3 VOUT1 / VOUT2

| 接口 | 电压 | 用途 |
|---|---:|---|
| VOUT1 | 3.3 V | 对外供电 / 外部给板供电 |
| VOUT2 | 5 V | 对外供电 / 外部给板供电 |

手册前文给出的能力为：

- 3.3 V：最大约 500 mA
- 5 V：USB 供电时最大约 500 mA；外部供电时前文写最大约 1000 mA

但在后面的电源接口说明中又统一描述为“功率不大（最大 500 mA）”。因此如果准备带舵机、电机、继电器等大负载，**不要把板载 VOUT 当成大功率电源使用**。

板上 VOUT 还加入 TVS 管用于一定程度的浪涌、反接和感性负载保护，但这不等于可以直接安全驱动大电流电机或多舵机。

不能只看“ESP32-S3 有多少 GPIO”，而要看：

> **这个 GPIO 在 DNESP32S3 板子上已经接了什么。**

例如 IO8 已接红外发送电路，官方手册明确提醒它不适合作为普通输入检测脚使用，因为可能受到板载外设干扰。

## 11. 主要资源冲突关系

开发时建议优先记住以下几组冲突：

### 11.1 RGB LCD ↔ 摄像头

大量 RGB 数据线与摄像头 D0～D7、PCLK、VSYNC、HREF 共用 GPIO。

### 11.2 RGB LCD ↔ 音频 I2S

部分 LCD 数据脚与：

- I2S_MCLK
- I2S_SCK
- I2S_LRCK
- I2S_SDIN
- I2S_SDOUT

复用。

### 11.3 TF 卡 ↔ SPI LCD

两者共用 SPI 总线，需要正确管理 CS 和驱动初始化。

### 11.4 IO0 多重复用

IO0 同时涉及：

- BOOT
- I/O 扩展 INT
- DS18B20 / DHT11

不能随意使用。

### 11.5 IO2 多重复用

IO2 同时涉及：

- TF_CS
- 红外接收

### 11.6 IO8 多重复用

IO8 同时涉及：

- RGB LCD
- ADC
- 红外发送

## 12. 跳线帽相关

这块板上存在多处跳线配置，使用某个功能前应检查跳线帽。

### P4：USB 串口选择

用于连接 CH340C 与主控 UART0。

### P3：多功能接口

通过跳线帽改变功能：

- 1-2 短接：ADC 输入
- 2-3 短接：红外发送

如果某项功能“代码看起来没问题但硬件不工作”，跳线帽状态应作为第一批检查项。

# 13. ESP-IDF 使用前必须注意的问题

官方《使用前必看说明》主要提醒了以下 4 件事。

## 13.1 `dir_sdi()` 函数找不到

影响的官方实验范围：

`28_chinese_display` ～ `32_videoplayer`

原因：

ESP-IDF 的 `ff.c` 中把 `dir_sdi()` 定义成了 `static`，外部源文件无法直接调用。

官方资料给出的处理方式：

1. 找到 ESP-IDF 的 `components/fatfs/src/ff.c`；
2. 将：

```c
static FRESULT dir_sdi(...)
```

修改为：

```c
FRESULT dir_sdi(...)
```

3. 在 `ff.h` 中增加对应函数声明；
4. 官方示例中提到在 `ff.h` 约第 338 行进行声明；
5. 修改后最好先擦除 Flash，再重新编译工程。

手册给出的示例路径基于 **ESP-IDF v5.1.2**，如果你安装的是其他 ESP-IDF 版本，目录和源码实现可能不同，不应机械照抄行号。

---

## 13.2 TF / SD 卡兼容性

官方实际测试过：

- SanDisk 16 GB
- SanDisk 32 GB
- Lexar 32 GB
- Kingston 32 GB

手册确认这些卡可以正常读写。

对于：

- 32 GB 以上容量；
- 其他品牌或型号；

官方文档没有给出保证，需要根据实际卡型、文件系统及 ESP-IDF 配置自行验证。

---

## 13.3 工程路径不能包含中文

官方例程要求：

> **在全英文路径下编译。**

推荐：

```text
D:\esp32\DNESP32S3\examples\...
```

避免：

```text
D:\桌面\开发板\实验\...
```

否则可能出现编译器、CMake、Python 工具链或依赖脚本相关路径问题。

---

## 13.4 已生成 build 的工程不要直接换目录继续编译

如果工程已经生成过 `build/`，然后整个工程被移动到其他路径，原 build 缓存中的绝对路径可能仍指向旧位置，从而导致编译错误。

官方建议先擦除/清理，再重新编译。

更通用的做法是：

```bash
idf.py fullclean
idf.py build
```

如果只是下载/运行问题，也可以结合实际情况重新擦除 Flash 后烧录。

# 14. 推荐的第一次开发检查流程

以下是根据两份手册整理出的实用流程。

## Step 1：先确认工程路径

- 全英文路径
- 尽量不要使用过深目录
- 不要直接带着其他电脑/其他路径生成的 `build/`

## Step 2：确认供电

- 初期使用 USB_UART 供电
- 大负载外设不要默认从板载 3.3 V / 5 V 排针取电
- 电机、舵机等应重点考虑独立供电和共地

## Step 3：确认 GPIO 是否冲突

使用一个 GPIO 前，先检查：

1. IO 表；
2. 原理图；
3. 板载外设占用；
4. 跳线帽状态。

## Step 4：确认外设总线

尤其注意：

- 摄像头 ↔ RGB LCD
- 音频 I2S ↔ RGB LCD
- TF 卡 ↔ SPI LCD
- USB / UART 跳线

## Step 5：编译前清理旧缓存

如果工程换过目录或修改过底层 ESP-IDF 文件：

```bash
idf.py fullclean
idf.py build
```

## Step 6：遇到 TF 卡问题先做最小验证

先只初始化 TF 卡，不同时启动 LCD、摄像头等其他复杂外设，确认：

- 卡是否识别；
- 文件系统是否挂载；
- SPI 引脚和 CS 是否正确；
- 卡容量/格式是否兼容。

# 15. 最值得记住的结论

1. **核心资源足够丰富**：ESP32-S3 + 16 MB Flash + 8 MB PSRAM，可以承担比较复杂的音频、显示、摄像头和 AIoT 项目。
2. **板载外设很多，但代价是 GPIO 冲突明显**。
3. **RGB LCD 是 GPIO 大户**，与摄像头和音频存在大量复用关系。
4. **TF 卡和 SPI LCD 共用 SPI**，实际开发前应核对原理图和示例工程。
5. **板载 ES8388 + MIC + 功放 + 扬声器已经形成完整音频链路**。
6. **USB_UART 是主要供电和串口下载口，USB_SLAVE 可用于原生 USB/JTAG**。
7. **大负载不能只看“有 5V 输出”就直接接**，供电能力、压降、浪涌和共地都需要单独设计。
8. **官方 IDF 例程最好放在全英文路径中**。
9. **工程移动目录后应清理 build 缓存再编译**。
10. **手册自身存在少量前后不一致描述，关键总线和引脚最终应以原理图 + 示例源码 + 实测为准。**

## 16. 资料中的两处重要不一致

为了避免后续开发时被文档误导，建议特别标记：

### TF 卡总线

- 资源概览：写作 SDIO
- 原理图详解：写作 SPI，并注明与 SPI LCD 共用总线

**实际使用前必须进一步核对原理图和官方 TF 示例。**

### USB HOST / SLAVE 引脚名称

- 一处文字写 `PA11 / PA12`
- IO 分配表写 USB D-/D+ 为 `IO19 / IO20`

这两种命名显然不能直接同时成立。针对 ESP32-S3 实际工程，应以对应板卡原理图及官方 ESP-IDF USB 配置为准。

## 17. 后续开发建议维护一张 GPIO 占用表

建议每增加一个模块，就在项目中维护：

```markdown
| GPIO | 当前用途 | 板载默认用途 | 是否冲突 | 备注 |
|---|---|---|---|---|
| IO41 | I2C SDA | AP3216C / ES8388 I2C | 否/共享 | I2C 总线共享 |
| IO42 | I2C SCL | AP3216C / ES8388 I2C | 否/共享 | I2C 总线共享 |
| IO11 | TF MOSI | SPI2 MOSI | - | TF/SPI LCD 共总线 |
| IO12 | TF SCK | SPI2 SCK | - | TF/SPI LCD 共总线 |
| IO13 | TF MISO | SPI2 MISO | - | TF/SPI LCD 共总线 |
```

对于这块开发板，这张表会比单纯记忆“ESP32-S3 有哪些 GPIO”更重要。
