# 语音与记忆改进实施记录

本批实现对应 [改进方案](voice-memory-improvement-plan-2026-11-01.md) 的 A、B、C 代码改动。没有部署或重启现有服务，没有迁移/修改真实聊天数据库；新增表在临时库及真实数据库的备份副本中验证。

## 已落地

| 范围 | 实际行为 |
| --- | --- |
| 文本分段 | 小数点跨片段保留；首段默认 18 字后可在短语标点输出，后续仍按较长句段，0 可关闭 |
| 阶段计时 | 首文字、首句、合成请求、首 PCM、首音频，及请求数、音频包数/字节/时长；测试页与汇总脚本可读 |
| 历史检索 | SQL 中先按匹配词数量排序，再按时间；近期消息 ID 排除，避免重复注入 |
| 长期事实 | SQLite 保存事实键、内容、类别、优先级、来源原文、关键词、时间和版本状态 |
| 纠正/遗忘 | 同键更新，旧事实退出当前注入；旧主题消息排除、摘要对应句子清理；旧批次不能恢复较新的改口或遗忘 |
| 闲时整理 | 默认空闲 20 秒的一次性计时，批次一次模型请求同时更新摘要和事实；新活动取消后台任务，无轮询 |
| 显式命令 | “记住”“忘掉”直接处理当前命令，当轮实际落库后确认；不被旧消息积压挡住，也不跳过待整理历史；普通问题没有额外记忆模型请求 |
| 管理与显示 | 事实查询、更新、遗忘 API，原有全设备清除涵盖事实，测试页显示有效事实 |
| 中断连续性 | 记录实际发出音频的段落；部分段落明确标注，未发送后文不进入对话 |
| 原生分轮 | 闲置静音使用短缓冲、不占本轮录音时长；到上限自动提交；自动切手动模式正确生效 |
| 接入一致性 | 普通 LLM 和 MCP 都使用合并后的系统资料，避免 GLM 忽略前面的角色或记忆 |

没有加入向量数据库、外部记忆服务、后台扫描或复杂衰减规则。用户隔离仍基于设备，不包含声纹识别。

## 验证证据

离线 375 项 Python、16 项浏览器逻辑测试通过，源码与脚本 compileall、git diff --check 通过。新增测试覆盖旧库增量建表、跨重连/重新打开保留、改口、遗忘、跨设备隔离、原文滚动清理后的事实保留、上下文预算、来源校验、后台取消、管理 API，以及打断后的发送记录。当前明确命令与历史积压分开处理、不推进历史游标；已遗忘事实仅向整理模型提供键和状态，后续摘要也继续清理该主题，避免旧内容被重新带回。

真实模型使用合成的咖啡偏好，并在临时库中验证。GLM 曾把类别写成 `identity/preference`，把遗忘当成 upsert；因此减少了重复模型字段，类别由事实键推导，明确遗忘以用户请求决定。没有通过接受任意来源或忽略错误来掩盖失败。

实际结果与跨会话回答见 [记忆在线检查 JSON](memory-live-check-2026-11-01.json)。最后一次检查记住、更正、遗忘分别等待 5.31、5.49、3.00 秒，跨会话回答正确，重新打开后仍保持遗忘。检查有随机性，单批通过不代表所有表述的准确率。显式整理的单次模型等待约数秒，普通闲聊的整理在后台进行。

[单次真实语音检查](voice-live-check-2026-11-01.json) 输入为已有的 2.064 秒合成语音，使用真实 SenseVoice、GLM、Edge TTS 与 Opus，输出按实机节奏发送到本进程 Transport：

## 真实 WebSocket 串行量化

[原始结果](voice-websocket-benchmark-2026-11-01.json) 使用实际 SenseVoice（CPU）、glm-4-flash、Edge TTS 和 Opus，启动本机随机端口隔离实例。输入固定为 2.064 秒合成录音，每轮新设备 ID、没有历史资料；预热 1 轮后测量 30 轮，30 轮均成功。回复约束相同，实际生成长度会变化。测试不使用现有运行实例、真实聊天正文或真实设备。

除独立阶段 ASR/记忆外，下表时间均以服务端开始处理已提交录音为起点，不能逐行相加。

| 指标 | P50 | P95 |
| --- | ---: | ---: |
| ASR | 93.3 ms | 108.7 ms |
| 本地记忆读写（空历史） | 1.4 ms | 1.5 ms |
| 首文字 | 699.2 ms | 4140.9 ms |
| 首句 / 首次 TTS 请求 | 889.6 / 889.7 ms | 4307.1 / 4307.1 ms |
| 首 PCM | 3470.4 ms | 6918.3 ms |
| 首音频发送 | 3471.7 ms | 6919.9 ms |
| 客户端收到首音频 | 3474.1 ms | 6922.5 ms |
| 服务端 pipeline 结束 | 7619.3 ms | 11911.2 ms |
| 客户端收到结束 | 7620.6 ms | 11912.8 ms |
| 输出音频帧时长 | 3690 ms | 6291 ms |
| TTS 请求数 | 1 | 3 |

按每轮先相减再统计：首文字到首句为 155.3 / 456.5 ms，TTS 请求到首 PCM 为 2448.7 / 2916.6 ms，PCM 到首 Opus 为 1.6 / 1.7 ms（P50 / P95）。TTS 是常规等待的大头，首文字的长尾也明显；当前没有证据支持优先更换 ASR 或去掉 60 ms 发送节奏。

启动提供者和监听器耗时 3.785 秒；进程峰值常驻内存约 3066 MiB。包含预热的串行测试历时 260.2 秒，进程 CPU 时间 12.02 秒，平均为一个 CPU 核的 4.6%；这不是整机 CPU 利用率或并发容量。ASR 使用 CPU，未测得本进程 GPU 分配。内存数字含模型和运行时，空闲常驻值、并发负载未在本次量化。

这里的“7.62 秒”是提交录音后至客户端收到音频发送结束，**不包含用户讲话的 2.064 秒、VAD 等待、ESP32 网络与播放队列**。真实说完到出声/播完仍需设备侧验证。本次固定短录音、空历史场景也不能代表长句、工具、视觉或大量历史检索的总体延迟。

## 有历史时的本地记忆耗时

[检索数据](memory-retrieval-benchmark-2026-11-01.json) 在独立临时 SQLite 中放入合成历史。非空场景有 20 条有效事实、一个摘要，摘要游标初始落后 10 条消息；默认原文保留上限为 5000。每种规模预热 3 次检索后测 30 轮，每轮插入一条问题并执行实际 `recall_for_turn`，不调用模型。初始空库在测量中也会累积这些问题。

| 初始历史数 | 写入 P50 / P95 | 检索 P50 / P95 | 合计 P50 / P95 |
| --- | ---: | ---: | ---: |
| 0 条、无事实 | 0.2 / 0.3 ms | 0.4 / 0.5 ms | 0.6 / 0.8 ms |
| 500 条、20 条事实 | 0.4 / 0.5 ms | 2.0 / 2.2 ms | 2.4 / 2.7 ms |
| 5000 条、20 条事实 | 1.8 / 1.9 ms | 16.2 / 16.5 ms | 18.0 / 18.4 ms |

非空场景每轮返回 20 条事实、5 条相关历史，近期消息随未整理问题增加；历史资料字符量约千字。这说明当前合成规模下本地记忆操作不是秒级语音等待的主因，不能把空历史的 1.4 ms 推广到所有历史规模。该测量不是实际聊天内容的语义召回率，也不代表多设备并发、超长消息或冷缓存性能。

## 首段切分的受控比较

[完整数据](voice-segment-benchmark-2026-11-01.json) 使用固定文字流：先提供 18 字短语，600 ms 后补齐后文。实际调用 Edge TTS、Opus，并按设备节奏发送；每种模式预热一次、测量 30 次，交替顺序。没有真实 ASR、LLM、网络 WebSocket 或扬声器。

| 指标 | 整句 P50 / P95 | 短首段 P50 / P95 |
| --- | ---: | ---: |
| 首句就绪 | 601.8 / 602.3 ms | 1.3 / 1.4 ms |
| 首音频 | 2885.7 / 3140.0 ms | 2435.9 / 3084.7 ms |
| 发送完成 | 9522.0 / 9776.9 ms | 9644.1 / 10281.8 ms |
| 音频帧时长 | 6540 / 6540 ms | 7080 / 7080 ms |
| TTS 请求数 | 1 / 1 | 2 / 2 |
| 最大包间隔 | 62.8 / 63.6 ms | 63.0 / 76.3 ms |

这个固定场景首音频中位数提前约 450 ms（15.6%），P95 仅提前约 55 ms；30 对中有 26 对更早开口。代价是多一次请求，合成音频增加 540 ms，发送完成中位数慢约 122 ms、P95 慢约 505 ms。最大包间隔包含正常 60 ms 帧节奏，不等同于扬声器听感。短首段有开口收益，但不能声称整轮总时长普遍缩短；保留可配置开关，后续仍按长句合成，语气自然度待实机确认。

## 端点等待比较

[VAD 数据](vad-endpoint-check-2026-11-01.json) 用实际 Silero ONNX 对同一条合成语音、0.7 倍速版本及插入停顿的版本判断语音，再比较 450/600 ms 端点。60 ms 帧使 450 ms 实际在 480 ms 边界触发。

正常、慢速、插入 300/450 ms 停顿均保持一段；插入 540 ms 停顿时，450 ms 阈值切为两段，600 ms 保持一段；900 ms 停顿两者均分段，纯静音均不提交。**因此默认继续保留 600 ms**。这证明降低阈值存在句中误截风险，合成样本不能给出真实人声截断率，仍需慢说和自然停顿实测。
