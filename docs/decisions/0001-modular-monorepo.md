# 0001：采用模块化单仓库

- 状态：已接受
- 日期：2026-08-05

## 背景

项目只有 6 人，但固件、服务端、协议和机械文档需要频繁联调。若过早拆成多个仓库，协议更新、版本配套和 Issue 跟踪会产生额外协调成本。

## 决策

MVP 阶段使用一个 GitHub 仓库，并通过顶层目录明确所有权。`protocol/` 是固件与服务端的共享边界，协议变更需要双端审核。

## 后果

- 优点：一次 PR 可原子更新协议、示例和两端适配；里程碑与 Issue 集中。
- 代价：仓库会包含不同工具链，CI 应保持按目录触发。
- 复审条件：某个模块出现独立发布节奏、权限隔离或仓库体积问题时，再评估拆仓。
