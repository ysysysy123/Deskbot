个人主责：服务端语音与对话
01

模型评测与选型

↗

Linux + Conda 复刻 ASR/TTS 对比实验；固定输入、预热与五次重复测试；记录加载、推理、显存、首音频和 RTF，形成统计与试听产物。

02

语音服务基础链路

↗

实现 Python 语音服务，兼容小智 WebSocket v1；接入 Silero VAD、SenseVoice、OpenAI 兼容 LLM、EdgeTTS、FFmpeg 和 Opus 编解码。

03

连续对话与播放体验

↗

自动分轮、回复后恢复监听、分句合成、音频按 60 ms 帧节奏下发；浏览器持续对话支持说话打断并取消旧轮。

04

设备记忆与扩展接口

↗

SQLite 保存历史与摘要，按设备隔离，提供简单相关检索及管理 API；通过 Provider 与 DialogueBackend 解耦语音链路和模型。

05

工具调用与视觉联动

↗

MCP 初始化、工具发现、会话绑定与调用返回；接入拍照、姿态、运动工具，将视觉分析结果接回语音输出。承担语音侧集成与跨模块联调。

06

测试界面与运行工具

↗

文字、录音及 WAV 测试入口；在线设备、历史、耗时、日志和模型测速；桌面启动与停止入口，支持 ninfer、Ollama、智谱配置选择。

07

稳定性与故障修复

↗

就绪检查、旧会话替换、超时与取消、空回复修复、本地命令 TTS 接口；定位并修复 EdgeTTS 403，协同定位实机摄像头工具缺失。

AUDIO / 输出与中断

边生成，边衔接播放。

  1. 01

    文字按句入队

    后续文本接收与语音合成并行。

  2. 02

    音频流式转码

    Edge 音频到达后转 PCM，再编码 Opus。

  3. 03

    按帧节奏下发

    避免长回复集中涌入设备播放队列。

  4. 04

    中断旧轮，接收新句

    取消生成和旧播放，回收转码资源。

能力范围 浏览器支持回复期间 VAD 自动打断；原生 ESP32 支持协议取消，尚未增加同样的自动打断。

    模型实验

    历史聊天《复刻 ASR 和 TTS 模型对比测试》保存的正式实验读取输出及交接记录。每项重复 5 次，预热不计统计。本地模型使用 CUDA，EdgeTTS 为云端请求。

    ASR 图显示各语言样本的推理中位数；TTS 图显示各类文本的首音频或总耗时中位数。这里没有准确率、自然度评分或置信区间。Qwen3-TTS 的本次适配器为整段生成，首音频等于总生成时间。

    原始 JSON/CSV 本次未在当前目录找到；所展示数字依据历史保存输出，不是新一轮测量。

    归属与能力范围

    个人工作按服务端语音、模型实验、设备工具接入和联调归纳。硬件驱动及独立视觉模块属于团队协作；采用现有模型，没有声称自研模型训练。

    当前配置依赖云端 LLM、视觉与 EdgeTTS。浏览器自动打断不代表原生 ESP32 已具备同样能力；多连接支持不代表已完成容量压测。
