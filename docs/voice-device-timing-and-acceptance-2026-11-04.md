# 设备侧语音计时与后续验收

日期：2026-11-04。本轮按用户选择完成代码、构建和离线验证，未烧录或进行实机测量。

## 计时范围

服务端 `tts.start` 增加可选 `turn_id`，与本轮日志的会话／代次对应；原有音频格式与二进制帧不变。固件将这个 ID 与解码器播放代次一起记录。旧服务未提供 ID 时，使用该连接的设备本地顺序 ID。

所有下列时间均来自设备自己的 `esp_timer_get_time()`，单位为微秒；不与服务器时钟直接相减。

| 事件／字段 | 实际采样位置 |
| --- | --- |
| `first_output.voice_end_us` | AFE 最近一次从讲话转为静音的时间，在本轮 TTS 开始重置解码器时固定快照 |
| `first_output.received_us` | 本轮首个音频包成功进入解码队列 |
| `first_output.output_us` | 本轮第一次调用 codec `OutputData` 之前，回调在写入返回后递交，不增加写入前日志等待 |
| `drained.drained_us` | 输出后解码／播放队列及在途工作均为空的时间；流中欠载也可能产生排空事件 |
| `barge_in.detected_us` | 设备 VAD 检测到本次讲话的时间 |
| `barge_in.reset_us` | 本地解码／播放队列清理返回时间，早于网络中断请求 |

主线程按播放代次匹配日志，避免把旧输出回调归入新轮次。解码重置在接受 `tts.start` 时完成，再进入 speaking；后续状态事件不再清空已经收到的新轮次首包。

## 汇总串口日志

在 `server/voice` 目录执行：

```bash
python scripts/summarize_device_timings.py /tmp/deskbot-serial.log --json /tmp/device-timings.json
```

脚本只读取 `Voice timing:` 结构化事件，输出各指标实际样本数、P50/P95 和轮次事件，不复制其他串口内容。没有 VAD 锚点的手动／文本轮次，不会被当作 0 ms 的语音结束延迟。

指标为：设备 VAD 结束到输出调用、首包入队到输出调用、输出到最后观测排空、VAD 讲话到队列清理。最后观测排空不等同于整段回答完成确认；日志应在测试回合结束后再汇总。

codec 输出调用、软件排空和清理都是设备内部里程碑。实际“人说完到喇叭出声”“插话到喇叭停音”，仍使用同一条外部录音的时间线测量。

## 实机开放后的验收

| 场景 | 待记录结果 |
| --- | --- |
| 普通短语音至少 30 回合 | 服务端与设备事件按 turn_id 关联；设备输出代理与外部录音首声分别统计 |
| 正常／较高音量下明确插话 | 成功数／总数、实际停音 P50/P95、旧音频残留、新指令首字完整性 |
| 仅机器人说话与用户短附和 | 回声误触发、附和被当成插话的次数 |
| 句中停顿和连续两轮插话 | 是否误切、漏掉首字、回合串音 |
| tts.stop 已到达但设备仍播放尾音时插话 | 尾音能清空，新回复不会因等待第二个停止报文而被屏蔽 |
| 自动监听静音超过两分钟后再说话 | 连接保持、录音上限不被闲置消耗、恢复后能完成对话 |

300 ms 的实际插话停音 P95 仍是待验目标。本轮离线集成测试已验证 abort → realtime listen/start → 预录音 → 新回复的协议与 Opus 链路，尚无实机延迟、回声或听感结论。
