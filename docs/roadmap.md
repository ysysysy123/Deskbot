# MVP 路线图

路线图按“可演示闭环”排序，不按模块完成度排序。日期由团队在第一次周会中填写。

## M0：接口冻结

- [ ] 确认开发板、屏幕、麦克风、扬声器、电机和供电方案。
- [ ] 给 6 个角色绑定 GitHub 用户名。
- [ ] 评审 `protocol` v0 envelope 和第一批消息类型。
- [ ] 建立统一接线图、BOM 和硬件照片记录方式。

验收：所有成员能说清自己的目录、输入、输出和首个 Issue。

## M1：设备控制闭环

- [ ] ESP32 启动并输出硬件自检结果。
- [ ] 本地 WebSocket 服务接受 `session.hello`。
- [ ] 服务端下发 `device.command`，设备用 LED 或串口模拟动作。
- [ ] 设备返回带相同 `correlation_id` 的 `device.event`。

验收：拔掉并重连网络后，设备可恢复会话并再次执行命令。

## M2：语音闭环

- [ ] PC 麦克风和扬声器先完成 ASR → LLM → TTS。
- [ ] 明确 Opus 编码、采样率、帧长与传输方案。
- [ ] 将音频输入输出迁移到 ESP32。
- [ ] 说话期间有屏幕或灯光反馈。

验收：完成连续 10 轮语音对话，记录延迟和失败原因。

## M3：动作、表情与视觉

- [ ] 建立至少 3 个表情和 3 个安全动作服务。
- [ ] 摄像头图像可送到视觉模块并返回结构化描述。
- [ ] LLM 只能通过白名单命令触发动作。
- [ ] 机械结构完成线束固定、散热和倾倒风险检查。

验收：语音和视觉可触发受限动作，异常命令不会执行。

## M4：桌面宠物演示版

- [ ] 角色提示词与配置可替换，但不写入固件。
- [ ] 有待机、聆听、思考、说话、错误五种状态反馈。
- [ ] 完成断网、服务异常、重启和长时间运行回归。
- [ ] 输出装配说明、演示脚本和已知问题。

验收：新成员按文档完成部署，并稳定演示 30 分钟。
